W7-2 RELIABILITY (packages/marketing/src/adapters/sources/youtubePublish.ts):
- The byte upload now speaks the REAL resumable protocol's durability
  semantics: a 308 with a Range header is a partial commit — the connector
  resumes from the session's durable offset and NEVER re-sends committed
  bytes (the interrupted-upload test asserts the resume PUT carries exactly
  `bytes 4-7/8` and a 4-byte body after a 4-byte durable prefix).
- Transient failures (5xx / transport errors) retry a BOUNDED number of times
  (3 attempts, 250ms linear backoff) on the idempotent session init and on
  every GET route (videos.list verification, analytics reports); persistent
  transients surface as the typed transient_network after exactly the
  bounded attempts — never an unbounded loop, never a silent success.
- Quota (429) surfaces immediately as the typed rate_limited with the quota
  scope and retry hint: the connector never sleeps across a quota window
  guessing at the platform's reset time (the host's retry policy and the
  caller decide; the W3-3 evidence shows the host already retries
  honorably).

W7-3 TENANT ISOLATION (plugin test/w7-isolation.test.ts):
- Missions are isolated tenants: every cross-mission id is a typed refusal
  (unknown_artifact / unknown_publication / unknown_experiment /
  unknown_import) across review/publish/verify/measure/outcome tools — no
  accidental cross-tenant reads; import ids resolve only inside their own
  mission's asset directory; loop state lists only the calling mission's
  records.
- Persistence: per-mission artifacts files only; no persisted record carries
  an absolute host path (paths stay .zcode-relative).
- The connection store's contract is stated and asserted explicitly: ONE
  workspace-global publishing account per platform (the user's own account),
  shared across their missions, token confined to the credential area.
