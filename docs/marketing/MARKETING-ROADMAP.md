- **Exit gate:** at least one viable organic-content source and one suitable ad-intelligence source for the intended market have verified access paths and repeatable test results.
- **Status:** ✅ Complete (2026-10-29). Contracts frozen and implemented (`packages/marketing/src/domain`, `app/ports.ts`, connector contract, capability catalog). **Initial market recorded: United States / YouTube.** Organic side: keyless YouTube public routes — `connector:youtube-public`, live repeatable test `evidence/2026-10-28-w1-source-access-youtube-public.txt` (verified 2026-10-28; 2026-10-29 route-availability incident recorded in the ledger, surfaced as explicit coverage gaps). Meta Ad Library API remains the credentialed growth path (not a W1 blocker).

### W2 — Temporal data foundation
- Connector framework, normalized entities, provenance, immutable metric observations, historical snapshots, coverage reporting, backfill where permitted.
- **Exit gate:** ingesting the same evidence twice is safe, metric changes are recorded, and an as-of query reproduces the observations actually available at that time.
- **Status:** ✅ Complete (2026-10-28). `app/temporalStore.ts` defines `TemporalStorePort`; the in-memory implementation and the production SQLite persistence adapter (`adapters/sqliteStore.ts`, `node:sqlite`, repo-style immutable versioned migrations) both pass the identical gate set — idempotent ingest, duplicate no-op, explicit revisions preserved in an append-only revision table, as-of queries, velocity, plus close/reopen persistence (`evidence/2026-10-28-w2-sqlite-persistence-conformance.txt`). MarketingMission accepts an injected store; workflows are storage-agnostic.

W3-2 (2026-10-29): structured extraction routes through the host MCP sampling channel with `zcode:routed:<model>` provenance and labeled heuristic fallback (`evidence/2026-10-29-w3-2-sampling-bridge-run.txt`). ### W4 — Creative strategy and production handoff
- Structured creative brief, generator-specific prompts, scripts, storyboards, testable hypotheses; asset upload, comparison, validation.
- **Exit gate:** the user can take a recommendation into a creative platform, produce an asset, and bring it back into the same marketing mission.
- **Status:** ✅ Complete (2026-10-29, W4-1). The full production pack (`marketing_draft_creative`: brief, timed 4-beat script, storyboard, video-gen/thumbnail/copy prompt packs, testable experiment spec, drafting provenance) → explicit review/approval (`marketing_review_artifact`, invalid transitions refused) → chunked bring-back (`marketing_asset_import_*` into the mission workspace, byte-count verified) → the versioned validation rubric (`RUBRIC_VERSION v1`: deterministic rule checks + routed qualitative assessment with provenance; suggests, never edits) → comparison (`marketing_compare_assets`). Hypotheses persist with content-stable ids; creative state is restart-safe (`.zcode/marketing/missions/<id>-artifacts.json`). The workspace panel's Creative tab renders the whole handoff (draft → approve → bring-back with a real file chooser → rubric report). Evidence: `evidence/2026-10-29-w4-creative-handoff.txt` (31 gates, real spawned server), W4 gates in `evidence/2026-10-29-w3-4-panel-e2e.txt` (browser), rubric suite 9/9, plugin suite 46/46.

### W5 — Authorized publishing
- Platform-specific publishing adapters, consent handling, approval controls, post-status verification, publication records; assisted/manual path for unsupported platforms.
- **Exit gate:** the system publishes a user-approved asset through a connected test account, verifies the resulting post, and records its identity.
- **Status:** ✅ Complete (2026-10-29). `connector:youtube-publish` implements the REAL YouTube Data API v3 wire protocol (resumable upload session → PUT bytes → videos.list verification; analytics capability for W6) with the closed organic publishing tool set (`marketing_connect_publish_account` health-checks a candidate account BEFORE persisting it, `marketing_publish_asset` idempotent per artifact, `marketing_verify_publication`, `marketing_assisted_handoff` + `marketing_record_manual_publication` for every unconnected case, `marketing_list_connections/_publications`). Connections persist in the workspace credential area (`.zcode/marketing/connections.json`, token never echoed — grep-enforced); every publication carries the connection's environment label (sandbox test-account posts are never presented as production). Evidence: `evidence/2026-10-29-w5-authorized-publishing.txt` (37 gates, real spawned server, bearer-validated local sandbox test endpoint speaking the real wire shapes; the manual path verified LIVE through the keyless public oEmbed route against a real public video) + browser gates 10-13 in `evidence/2026-10-29-w5-6-panel-e2e.txt`. Production googleapis OAuth remains the identical code path pending real channel credentials (recorded in MARKETING-DATA-SOURCES.md).

### W6 — Measurement and closed-loop learning
- Collect permitted analytics, compare actuals vs forecasts, run evaluation and backtesting, correct calibration, recommend the next experiment.
- **Exit gate:** the system completes at least one measured content experiment and produces a subsequent recommendation grounded in the recorded result.
- **Status:** ✅ Complete (2026-10-29). The measurement window opens on a publication (`marketing_open_experiment`, idempotent) and tests exactly what the W4 pack's experimentSpec declared (changed variables + window), binding the hypothesis's PRESERVED forecast. Permitted connected-account analytics collect through the Analytics API v2 shapes into the temporal store (idempotent ingest, coverage verbatim, sandbox label included). The outcome records through `marketing_record_outcome`: the forecast compares verbatim (never rewritten); a PROXY observation REQUIRES its own declared baseline (proxyForecast) — never silently compared against the goal metric's range, and without a baseline it is a typed refusal; the comparison carries the [PROXY] label; calibration history is APPENDED (calibration:v1 multiplicative correction); the next-experiment recommendation is grounded in the recorded result with the observation source as evidence. Evidence: `evidence/2026-10-29-w6-closed-loop.txt` (34 gates, real spawned server, sandbox test account analytics) + browser gates 14-15 in `evidence/2026-10-29-w5-6-panel-e2e.txt` (the loop closes through the rendered panel). Calibration against PRODUCTION outcomes begins with the first real publication (production connection pending real credentials).

## Critical sequencing decision

**Build one complete, measurable journey before building ten partial platform integrations.** The first platform and ad source are chosen after the W1 access test, with the intended market and geography explicitly defined. Connector-neutral architecture from day one, deliberately small verified set first.
